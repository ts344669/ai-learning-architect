# AI Learning Architect v0.9 — полный AI-цикл + учебные пакеты для преподавателя

## Что добавлено по сравнению с v0.8

- На экране 1 добавлена кнопка **«Загрузить учебный пакет»**. Пакет — небольшой JSON-файл с вымышленными данными; он читается локально в браузере, автоматически заполняет анкету и не сохраняется на сервере.
- В папке `teacher_packages/` лежат три готовых пакета: учебный дефицит, смешанная проблема и неучебная причина.
- Модель по умолчанию обновлена до `openrouter/free`. Для портфолио-версии используйте только вымышленные материалы: бесплатные модели OpenRouter имеют лимиты и могут меняться; используйте только вымышленные учебные материалы.

- Экран 1: существующая живая AI-диагностика. Подтверждение выводов методологом обязательно.
- Экран 2: кнопка **«Построить дерево и архитектуру с AI»**. Использует именно текущую анкету и подтверждённую живую диагностику, а не фиксированный пример C01.
- Экран 3: карточки и проверяемые признаки; доступно ручное редактирование основных текстовых полей. Сохранение помечает старый аудит как неактуальный.
- Экран 4: кнопка **«Проверить архитектуру с AI»** — оценивает актуальные карточки по 9 методическим критериям, объясняет основания и разрывы. Процент подсчитывает код. «Недостаточно данных» не считается нулём.
- Обычный демонстрационный пример сохранён и всегда подписан отдельно от живого AI. Неучебный кейс не открывает AI-дерево.
- Исходный KPI, целевой KPI, период и способ измерения определяет заказчик. Прогнозируемый эффект обучения не выдумывается, KPI не гарантирован. Банк из 37 возможных факторов оставлен в первом экране.
- Единый градиентный интерфейс и Verdana сохранены. API-ключ остаётся на сервере.

## Тестирование (выполнено)

`npm test` — 21 проверка, включая сквозные серверные маршруты с **имитацией ответа AI-провайдера**. Это проверяет структуру запросов и результаты, но НЕ качество ответов реальной модели.

Обязательные ручные проверки с настоящим ключом:
1. Выбрать C01, нажать «Проанализировать с AI», оценить заключение и подтвердить диагностику.
2. Открыть экран 2, нажать «Построить дерево и архитектуру с AI». Убедиться, что есть отдельные рабочие действия и их связь с исходной задачей.
3. Открыть экран 3, проверить карточки, изменить практику или способ оценки и сохранить.
4. Открыть экран 4, нажать «Проверить архитектуру с AI». Раскрыть 9 критериев. Если реальный ответ отличается от ожидаемого, проанализировать методическую ошибку.
5. Для C02 проверить отделение учебной части от ограничений CRM; неучебные действия не предписываются за заказчика.
6. Для C03 убедиться, что AI не строит дерево без обоснованного учебного дефицита.
7. Повторить этапы на собственной небольшой вымышленной задаче, чтобы убедиться: результат не заготовлен.
8. Проверить работу на ноутбуке и мобильном браузере. Это ещё не было подтверждено в текущем окружении.

## Локальный запуск

Требуется Node.js 20+.

1. Распакуйте ZIP.
2. Откройте терминал в папке проекта.
3. `npm start`
4. Откройте `http://localhost:3000`.
5. Для живого AI задайте переменную среды `OPENROUTER_API_KEY`, затем перезапустите сервер. **Никогда не вписывайте ключ в HTML/JS или GitHub.**
6. Дополнительно можно указать `OPENROUTER_MODEL` (по умолчанию `openrouter/free`). Доступность выбранной модели в вашем API-проекте нужно проверить.

Без ключа работает только демонстрационный режим — это нормально для первого просмотра, но для итоговой сдачи недостаточно.

## Размещение на Render

1. Загрузить исходники в отдельный репозиторий GitHub **без `.env` и без секретов**.
2. В Render создать Web Service из репозитория, Node, запуск `npm start`, либо применить `render.yaml`.
3. Установить `OPENROUTER_API_KEY` в разделе Environment Render, не в репозитории.
4. Настроить `MAX_AI_CALLS_PER_DAY` и `MAX_AI_CALLS_PER_IP_PER_DAY` (по умолчанию 20 и 4). Эти счётчики хранятся в памяти одного процесса и сбрасываются при рестарте — не гарантия ограничения расходов! Обязательно ограничьте квоты/бюджет на стороне AI-провайдера. Перед публичным запуском при необходимости усилите rate-limit и антибот-защиту.
5. Проверить `/api/status`, три тестовых кейса и собственную задачу по публичной ссылке.

## Честный статус проекта

v0.9 — новая сквозная логика и импорт учебных пакетов и работающие серверные интеграционные тесты **с имитацией ответов AI**. Реальный запрос к OpenRouter не выполнялся: API-ключ отсутствует. Публичная ссылка ещё не создана. До сдачи преподавателю обязательны живые испытания, визуальная проверка и публикация.

## Экономия

Нет новой базы данных, платных библиотек, внешних шрифтов и обязательной платной инфраструктуры. Каждый полноценный цикл делает максимум три осмысленных AI-вызова (диагностика, дерево+карточки, аудит); повседневное ручное редактирование не расходует токены. Повторный аудит — отдельный AI-вызов. Не загружайте настоящие конфиденциальные материалы: это демонстрационное приложение.
